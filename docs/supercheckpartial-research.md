# Super Check Partial (SCP) 竞赛呼号数据库调研

- 调研日期：2026-11-11（UTC+8）
- 调研对象：<https://supercheckpartial.com/>（实际访问站点、`/formats`、`/faq`、`/developers`、`/contribute`、`/lookup` 页面，并实际下载全部数据文件）
- 结论适用范围：DX-Compass（Node-RED + SQLite，SPOT 地图 / QSO 地图 / 大屏 / DXCC×波段倍率矩阵 / 条件告警 / 呼号→DXCC 解析）
- 说明：本报告只记录实际观测到的事实；无法确认的地方在文中和“未确认事项”中明确标注。站点是 SvelteKit 单页应用，直接抓取 HTML 只能得到空壳，页面正文取自 `/_app/immutable/nodes/*.js` 的模板字符串，数据文件与 API 则直接抓取验证。

## 0. 结论摘要

1. **数据可用**：SCP 提供 4 组基础名（master / masterdx / masusve / masterss）× 3 种格式（`.SCP` / `.DTA` / `.LIS`），外加完整的 `SCP.DB`（SQLite）。`MASTER.SCP` 仅 359 KB、5 万行，取用成本极低。
2. **格式已实测解码**：`.SCP` 是 CRLF 纯文本；`.DTA` 是“2 字符相邻组合”倒排索引（1,369 个桶 + 5,480 字节偏移表），不是简单的“按前两个字符分组”；`SCP.DB` 只有 1 张 `callsigns` 表（呼号 + 年出现率 + 位域元数据），**没有任何 DXCC / 网格 / 分区字段**。
3. **更新频率高**：站点声明每周重建两次；本次抓到的版本为 `Release 2026.11.06`，生成时间 `2026-11-06T00:01:10Z`。
4. **许可证不明确**：站点页脚是 “© … Super Check Partial Database — W9KKN. All rights reserved.”，sitemap 中没有 license/terms 页面，文件头也没有许可证声明。**不应把数据文件打包进 DX-Compass 仓库或发行包**；建议运行时从官方地址拉取、本地缓存、保留署名与版本号。
5. **对 DX-Compass 的最大价值不是“校验 DXCC”，而是“活跃竞赛台存在性”**：可用于告警/SPOT 的“疑似拼写错误”标记、相似呼号建议、活跃度排序；**不能**用来校验 DXCC 归属（SCP 没有实体字段），也**不建议**用来硬过滤 PSKReporter/DIGI 数据（会误杀非竞赛台和稀有台）。
6. **实现成本低**：50k 呼号的内存 `Set` 查询 O(1)，常驻内存约数 MB；每日一次条件 GET 即可，失败时沿用旧副本。建议做成默认关闭的可选功能，并加设置开关。

### 1.2 `MASTER.SCP`（实测）

原始前 8 行（`\r\n` 换行，纯 ASCII，无 BOM）：

```text
!!Order,1,1
#
# Super Check Partial
# Release 2026.11.06
# Generated by bb-scp
#
2D0OMN
2E0AOZ
```

- 总行数 50,026（含末尾空行）；6 行文件头；正文 50,020 行。
- 正文里 **50,019 个真实呼号 + 1 个版本伪呼号 `VER20261106`**（位于 `VE9XX` 与 `VJ2A` 之间，按字母序插入）。因此站点统计的 `master: 50019` 与文件实际行数相差 1，属于预期。
- 呼号按字母升序排列，无重复，全部大写；实测最大长度 11（如 `GM0FRT/P`、`N6QEK/KL7`、`I/DL3NC`）。
- 行首 `!` 或 `#` 为注释；`!!Order,1,1` 是给日志软件的排序提示，不是呼号。

### 1.3 `MASTER.LIS`（实测）

```text
     88 2D0OMN
    233 2E0AOZ
    445 2E0BLN
...
    161 ZZ7ZZ
```

- 50,019 行，格式为“右对齐的整数 + 空格 + 呼号”，按呼号升序。
- 第一列与 `SCP.DB` 的 `annual_rate` 完全对应（如 `2D0OMN` 两边都是 88）。
- 出现率范围实测 0–86,976；有 87 个呼号出现率为 0。
- `.SCP` 正文（除 `VER20261106` 外）与 `.LIS` 的呼号集合完全一致。

### 1.4 `MASTER.DTA`（实测解码）

站点 `/formats` 的原话是：

> Binary indexed file with 1,369 buckets (37 x 37, covering A-Z, 0-9, /). 5,480-byte offset table followed by null-terminated callsign strings grouped by their first two characters. Designed by K1EA.

实测结果与“按前两个字符分组”**不一致**，更准确的描述是：

- 文件开头是 **1,370 个 little-endian uint32**（5,480 字节），前 1,369 个是桶起始偏移，最后 1 个是文件长度哨兵（实测 `1,331,052`）。
- 字符集为 `A-Z 0-9 /`（37 个字符），桶索引 = `index(char[i]) * 37 + index(char[i+1])`，即 **37×37 的“相邻两字符”倒排索引**。
- 桶内是 `\0` 结尾的大写呼号字符串；同一个呼号会出现在它包含的每一个相邻字符对对应的桶里。
- 实测总数 209,089 条索引项；按“每个呼号所有不重复相邻字符对”重算得到 209,089（50,020 个正文条目，含 `VER20261106`），**完全吻合**。
- 随机抽 300 个呼号，预测其应出现的全部桶，300/300 命中。
- 例：`K1TTT` 同时出现在 `K1`、`1T`、`TT` 三个桶；`AA0AW` 出现在 `AA`、`A0`、`0A`、`AW` 四个桶。

> 结论：`.DTA` 是给“边输入边匹配”的 check-partial 用的二元组索引，不是简单的呼号列表。DX-Compass 若只需要“是否存在”，不必解析 `.DTA`；若要实现相似呼号建议，可以按同样思路在内存里自建 2-gram 索引，或直接复用官方 `.DTA`。

### 1.5 `SCP.DB`（实测）

SQLite 3 文件，`application/x-sqlite3`，2.83 MB。Schema：

```sql
CREATE TABLE callsigns (
    callsign    TEXT PRIMARY KEY,
    annual_rate INTEGER NOT NULL,   -- 估算的年出现次数（生命周期 QSO 数 / 活跃年数）
    modes       INTEGER NOT NULL DEFAULT 0,  -- 模式位域
    contests    INTEGER NOT NULL DEFAULT 0,  -- 赛事家族位域
    geo         INTEGER NOT NULL DEFAULT 0,  -- 地理位域
    verified    INTEGER NOT NULL DEFAULT 0   -- 来源/核验位域
);
CREATE TABLE metadata (key TEXT PRIMARY KEY, value TEXT NOT NULL, description TEXT);
CREATE TABLE examples (name TEXT PRIMARY KEY, query TEXT NOT NULL, description TEXT NOT NULL);
```

实测 `metadata`：

| key | value | 含义 |
|---|---|---|
| `generated` | `2026-11-06T00:01:10Z` | 生成时间 |
| `threshold_50k` | `181` | 约 5 万行平面文件所用最低年出现率 |
| `callsigns` | `69200` | 库内呼号总数 |
| `imported_files` | `1318517` | 已处理 Cabrillo 日志数 |
| `total_qsos` | `528366045` | 总 QSO 记录数 |
| `submitters` | `40044` | 合格提交者数 |

实测样本：

```json
{"callsign":"2D0OMN","annual_rate":88,"modes":2,"contests":1048578,"geo":1,"verified":17}
{"callsign":"2E0AOZ","annual_rate":233,"modes":27,"contests":6155,"geo":1,"verified":48}
```

位域定义（站点 `/developers` 原文）：

- `modes`：bit0 CW、bit1 Phone、bit2 FM、bit3 RTTY、bit4 Digital。
- `geo`：bit0 DX（非 US/CA）、bit1 US/Canada、bit2 Sweepstakes eligible。
- `verified`：bit0 SCP 提交者、bit1 比赛收到日志页、bit2 监管数据库（FCC/ISED/Ofcom）、bit3 LoTW、bit4 QRZ、bit5 HamQTH、bit6 手工添加。
- `contests`：bit0 CQ-WW、bit1 CQ-WPX、……共 27 个赛事家族（站点列出完整 0–26 清单）。

**重要发现**：

- `SCP.DB` 是 69,200 个呼号的超集；`MASTER.SCP` 的 50,019 个真实呼号全部能在 `SCP.DB` 中找到。
- `threshold_50k = 181` 并不能复现 5 万行：`annual_rate >= 181` 只有 33,814 个。平面文件的入选规则是“动态阈值 + 其他条件”，**不能简单用 `annual_rate` 阈值重建**。
- `geo` 位域也不等价于旧子集文件：`geo & 2 == 0` 有 47,625 个，而 `MASTERDX.SCP` 只有 35,949 个；子集文件还叠加了赛事参与度等过滤。不要假设两者等价。
- **`SCP.DB` 没有 DXCC 实体、前缀、网格、CQ/ITU 分区字段。** 它只能回答“这个呼号是不是活跃竞赛台”，不能回答“这个呼号属于哪个 DXCC”。

### 1.6 更新频率与版本标识

- 站点 FAQ / 首页 / Contribute 页一致声明：**数据库每周重建两次**，提交的日志进入下一次构建。
- 本次文件头：`# Release 2026.11.06`；`SCP.DB.metadata.generated = 2026-11-06T00:01:10Z`；HTTP `Last-Modified: Fri, 06 Nov 2026 00:01:38 GMT`。
- 可用版本判断：`.SCP` 文件头的 `Release YYYY.MM.DD`、`stats.json` 的 `generated`、`/api/v1/release` 的 `generated`、HTTP `ETag` / `Last-Modified`。
- 历史快照：FAQ 明确说**已移除**，不再提供历史归档。

### 2.1 直链

实测可用的地址（**文件名必须大写**）：

```text
https://www.supercheckpartial.com/MASTER.SCP

https://www.supercheckpartial.com/MASTERSS.SCP
```

同时支持 `https://supercheckpartial.com/downloads/MASTER.SCP`、`/downloads/SCP.DB`。实测：

- 小写 `master.scp` → 404；`/downloads/master.scp` → 404。
- `http://` 也能直接返回 200（未强制跳转 HTTPS），但应使用 HTTPS。
- 响应头带 `Content-Disposition: attachment; filename="MASTER.SCP"`，`Content-Type: application/octet-stream`；`SCP.DB` 为 `application/x-sqlite3`。

### 2.2 元数据 API

- `GET /api/v1/files`：返回全部文件的名字、字节数、`etag`、`modified`（ISO-8601）。适合做“发现文件 + 判断是否更新”。
- `GET /api/v1/release`：返回 counts / files / generated / regulatory。
- `GET /api/version`：站点自身版本（实测 `26.118.3`）。
- `GET /api/v1/search?q=K1T&limit=5`：前缀搜索，返回 `[{"callsign":"K1TTT"}, ...]`，**只有呼号，没有元数据**；空 `q` 返回 `[]`；`DL1ABC`（不在库中）返回 `[]`。该接口在 Developers 页面没有文档化，属于 lookup 页面内部使用，不建议作为主链路依赖。

### 2.3 抓取礼仪与限制（实测 + 官方指引）

- `robots.txt`：`User-agent: * / Allow: /`，并给出 sitemap；sitemap 只有 7 个页面，没有 license/terms。
- 官方 Developers 页面明确要求：
  - 使用条件请求（`If-None-Match` + `ETag`，或 `If-Modified-Since`）；
  - 遵守 `Cache-Control`，**轮询不要快于每天一次**（数据库每周只重建两次）；
  - 只下载需要的变体和格式；
  - 请求头带可识别的 `User-Agent`（含软件名和版本）；
  - 允许用户关闭自动更新。
- 实测响应头：数据文件 `Cache-Control: public, max-age=21600, stale-while-revalidate=21600`；`/api/v1/files` 为 `max-age=3600`。未观察到 `X-RateLimit-*` 或 `Retry-After`。
- 条件请求实测：
  - `If-Modified-Since: Fri, 06 Nov 2026 00:01:38 GMT` → **304 Not Modified**（符合预期）。
  - `If-None-Match: "<ETag>"` → 仍然 **200** 返回完整文件（CDN 边缘未命中 304）。因此实现时应**优先用 `If-Modified-Since`**，或两者都发但不要依赖 ETag 一定返回 304。
- 没有观察到访问频率限制或封禁；但仍应遵守“每天最多一次”的官方建议。

### 2.4 是否允许程序化抓取

站点没有 ToS 页面，但 Developers 页面是明确的“给日志软件集成用”的下载指南（条件 GET、UA、缓存、可关闭自动更新），可以视为**允许软件程序化下载**。这不等于允许再分发数据文件，见下一节。

## 3. 许可证与分发

### 3.1 实测到的声明

- 全站页脚：`© <year> Super Check Partial Database — W9KKN. All rights reserved.`
- sitemap 只有 `/`、`/contribute`、`/lookup`、`/request`、`/formats`、`/developers`、`/faq`，**没有 license / terms / privacy 页面**（直接访问这些路径只会返回 SPA 壳）。

- Contribute 页的数据政策：只保留呼号，不保留 QSO 细节；“All submitted files become the property of W9KKN for the purposes of maintaining the SCP database.”

### 3.2 结论

- **没有找到任何开源许可证或明确的再分发授权**；页脚是 “All rights reserved”。
- Developers 页面给出了下载与集成指引，可以理解为“允许日志软件在运行时获取数据”，但**没有授予把数据文件打包进仓库/发行版的權利**。
- 因此建议：
  1. **不要把 `MASTER.SCP` / `SCP.DB` 提交进 Git，也不要打进 release 包**；
  2. 运行时从官方地址下载到本地数据目录；
  3. 在界面/文档中署名：`Super Check Partial Database (W9KKN) — https://supercheckpartial.com — release 2026.11.06`；
  4. 若确实需要随包分发，先发邮件到 `logs@supercheckpartial.com` 取得书面许可；
  5. 提供“禁用 SCP 自动更新”的设置项。
- 以上是对站点文本的工程判断，不构成法律意见。

## 4. 典型用途与公开实现

### 4.1 日志软件怎么用

站点 FAQ 的描述（原文要点）：

- 输入呼号时，日志软件用 SCP 数据库显示可能的匹配，帮助更快、更准确地记录 QSO。
- N1MM+：`Tools` 菜单里有刷新 SCP 的入口；Win-Test、WriteLog 也支持自动更新；DXLog：`Options > Data files > Super check partials > Update`。
- 格式选择：N1MM+ / Win-Test 用 `.scp`，CT / TRlog 用 `.dta`，新软件推荐 `SCP.DB`。
- SCP 概念与原始 `.dta` 格式由 K1EA 为 CT 设计；数据库工具由 AD1C、K1EA 开发；当前维护者是 W9KKN（此前 K6TU、K5ZD、AD1C）。
- 入选标准是动态的：维护一个目标库大小，自动调整阈值；也可以提交日志或单独申请加入。

“check partial” 的实际行为在不同软件里细节不同（候选窗口、颜色、是否自动补全），本次没有逐个安装验证，报告中只采用站点原文能支持的部分。

### 4.2 可参考的公开解析实现

- **`github.com/ftl/hamradio/scp`（Go，MIT）**：提供 `MASTER.SCP` 的下载、更新（`Update` 只在需要时更新）、解析与查找 API；文档给出的格式描述是“ASCII 纯文本、每行一个呼号、`#` 开头为注释”。可作为 `.SCP` 解析与“条件更新”的参考实现。
  - <https://pkg.go.dev/github.com/ftl/hamradio/scp>
- 站点自身提供 `SCP.DB` 的 `examples` 表，内含可直接运行的 SQL（单呼号查询、按 `annual_rate` 排序、按模式位域过滤），可作为元数据查询参考。
- `.DTA` 的公开解析实现没有在本次调研中找到权威来源；本报告 1.4 节的解码结果来自对实际文件的逆向验证（300/300 抽样命中 + 总数精确吻合），可作为实现依据，但建议在代码中注明“实测逆向，非官方规范”。

## 5. 对 DX-Compass 的可用点

先明确一个前提：**SCP 是“最近 24 个月在提交日志中出现过的活跃竞赛台清单”，不是呼号合法性数据库，也不是 DXCC 数据库。**

### 5.1 能解决的问题

| 场景 | 做法 | 价值 | 主要风险 |
|---|---|---|---|
| 告警里过滤明显错误的呼号 | 用 `Set` 判断 `spot_call` / `de` 是否在 SCP；`scpAlertMode=drop` 时才丢弃 | 降低 RBN/dxwatch 垃圾 SPOT 和明显 bust 的弹窗/语音打扰 | 会误杀首次出现的 DXpedition、特殊呼号、非竞赛台 |
| SPOT 列表/告警卡片标注“不在 SCP” | 只加徽标，不改变数据 | 让操作者一眼判断“这个呼号像不像真实竞赛台” | 无（只是提示） |
| 拼写纠错/相似呼号建议 | 对未命中的呼号，用 2-gram 索引 + 编辑距离给出 Top-N 候选 | 减少手工纠正 bust、提高 QSO 录入准确率 | 只能“建议”，不能自动改写；相似不等于正确 |
| 活跃度排序/优先级 | 用 `SCP.DB.annual_rate`、`modes`、`contests` 给告警或邻台加“活跃度”权重 | 让“常见活跃台”与“冷门台”在排序上有区别 | 年出现率是相对统计，不等于本次比赛一定活跃 |
| 校验呼号是否能解析出 DXCC | 仅作为辅助：SCP 命中但 `resolveCall()` 返回 `dxcc:null` → 高度疑似拼写错误 | 帮助发现“前缀根本不存在”的 bust | SCP 本身不含 DXCC，不能反过来校验实体归属 |

### 5.2 不能解决的问题

- **不能校验 DXCC 归属**：`SCP.DB` 没有 DXCC 字段；`MASTER.SCP` 只有呼号。倍率矩阵的 DXCC 归属仍必须依赖 `public/shared/dxcc/callsign.mjs` 的前缀解析。
- **不能证明呼号“有效”**：不在 SCP 只说明“最近 24 个月没有出现在提交日志里”，可能是新呼号、稀有台、DXpedition、非竞赛操作员、或只是没提交日志。
- **不能用于过滤 PSKReporter / DIGI 数据**：FT8/FT4 有大量非竞赛、休闲操作员，本来就不在 SCP；用它过滤会系统性丢失数据，破坏现有 DIGI 链路和分析研判的样本代表性。
- **不能替代监管数据库**：SCP 的 `verified` 位域包含 FCC/ISED/Ofcom 等来源，但数据库本身不提供执照信息，不能用来判断呼号是否合法、是否过期。

### 5.3 与现有模块的结合点top

- **告警**：`lib/alerts/service.js` 的 `evaluate()`（约 289 行）已经构建 `context`（call / band / mode / source / dxcc / prefix），并调用 `stateFor()` 生成 `priority`。可以在这里加 `context.scpKnown`，并在 `candidate` 里带出 `scp: {known, annualRate}`；过滤逻辑放在“规则命中之后、写告警之前”，默认只标记不丢弃。
- **SPOT 记录/弹窗**：在 `public/shared/data/spots.mjs` / 前端渲染层增加徽标即可，不需要改数据库表。
- **倍率矩阵**：`lib/multipliers/service.js` 只从 `qsos` 表读数据、用 `resolveCall()` 解析 DXCC；**不要**把 SCP 塞进矩阵状态计算。最多在单元格的呼号列表里加“SCP”标记，或对“无法解析 DXCC 且不在 SCP”的 QSO 做提示。
- **邻台/分析研判**：`neighbors` 表和 PSKR 分析链路的样本总体不应被 SCP 过滤；可以在展示层标注“该邻台在/不在 SCP”，但统计口径保持不变。

## 6. 误判风险清单

1. **“不在 SCP = 无效呼号”是错误推论**。SCP 只覆盖最近 24 个月提交过日志的台站；新呼号、稀有台、DXpedition、临时呼号、不提交日志的台都可能不在库中。
2. **“在 SCP = 呼号正确”也不成立**。SCP 来自提交日志，日志里的 bust 会被收录；站点专门提供 removal request，理由就包括“frequent busts”。
3. **时间滞后**：每周只重建两次，大型比赛周末之后的新呼号可能几天内都查不到。
4. **格式差异**：SCP 是大写、精确匹配；`/P`、`/M`、`/QRP`、`/数字` 等便携后缀不一定以你以为的形式存在；`DL/EA1ABC` 与 `EA1ABC/DL` 可能只收录其中一种。直接 `Set.has()` 会产生假阴性。
5. **子集文件的语义不是位域的简单切片**：`MASTERDX` / `MASUSVE` / `MASTERSS` 与 `geo` 位域计数不一致，不能互相推导。
6. **元数据不是“比赛成绩”**：`annual_rate` 是年出现率，`contests` 是赛事家族位域，不能用来预测本次比赛的行为或功率。
7. **硬过滤会改变现有行为**：DX-Compass 目前的告警/地图对所有来源一视同仁；一旦默认开启 SCP 丢弃，会与既有“宁可多报”策略冲突。必须默认关闭、显式开启、并在 UI 说明。

## 7. 实现建议

### 7.1 数据选型

| 需求 | 推荐文件 | 理由 |
|---|---|---|
| 只要“是否活跃竞赛台” | `MASTER.SCP`（359 KB） | 最小、纯文本、解析零依赖 |
| 需要年出现率做排序 | `MASTER.LIS`（760 KB）或 `SCP.DB` | `.LIS` 是纯文本，最省事；`.DB` 元数据最全 |
| 需要模式/赛事/核验位域 | `SCP.DB`（2.83 MB） | 唯一带位域的格式 |
| 需要 2-gram 倒排索引 | `MASTER.DTA` 或运行时自建 | 自建更可控，避免二进制格式耦合 |

对 DX-Compass 的建议：**第一阶段只用 `MASTER.SCP`**；如果确实需要活跃度排序，再加 `MASTER.LIS`；`SCP.DB` 留到有明确 UI 需求时再上。

原因：项目 `install.sh` 要求 **Node.js >= 18**（`REQUIRED_NODE_MAJOR=18`），而内置 `node:sqlite` 需要 Node 22+；直接读 `SCP.DB` 会引入新的依赖/版本约束。若以后要读 `SCP.DB`，可以复用现有 Node-RED sqlite 节点，用 `ATTACH DATABASE 'SCP.DB' AS scp` 把数据导入本地表，避免新增 npm 依赖。

### 7.2 抓取与缓存

建议新增 `lib/scp/` 模块（纯函数 + 状态），由 Node-RED flow 定时触发：

1. **启动时**：读取本地缓存文件（如 `<APP_DIR>/scp/MASTER.SCP`），解析进内存；文件不存在则跳过，不阻塞启动。
2. **定时**：每天一次（例如本地时间 04:17，避开整点），用 `If-Modified-Since`（从本地 `state.json` 读取上次 `Last-Modified`）请求 `https://www.supercheckpartial.com/MASTER.SCP`。
3. **响应处理**：
   - `304` → 什么都不做；
   - `200` → 校验正文包含 `# Release` 且行数在合理范围（例如 40k–80k），写临时文件后原子 `rename` 覆盖，更新 `state.json`（`etag`、`lastModified`、`release`、`fetchedAt`、`count`），再重建内存索引；
   - 其他状态码/网络错误 → 保留旧副本，记录 `warn` 日志，状态接口标记 `stale`。
4. **请求头**：带 `User-Agent: DX-Compass/<version>`（官方要求）；不并发、不重试轰炸，失败等下一个周期。
5. **首次安装**：不要打包数据；首次启动时如果本地没有缓存，可以异步拉一次，失败就保持“SCP 不可用”，不影响任何现有功能。

### 7.3 存储形态：内存 `Set` 还是 SQLite

建议 **内存 `Map`/`Set` + 本地原始文件**，不建 SQLite 表：

- 50,019 个呼号，`Set<string>` 常驻内存约数 MB（V8 粗估 3–5 MB），完全可接受。
- 查询是 O(1)，不需要 SQL、不需要索引、不会与 `spots` 的 purge/retention 逻辑耦合。
- 原始文件保留在磁盘，重启时秒级加载，不依赖网络。
- 如果以后要 `annual_rate`，用 `Map<call, rate>` 即可（50k 条，额外几 MB）。
- **不要**把 SCP 数据写进 `dxcompass.db`：它是外部维护的数据集，混入业务库会让备份、清理、迁移都变复杂。

### 7.4 相似呼号建议（可选）

- 加载时用 50k 呼号自建 2-gram 倒排索引（与 `.DTA` 同思路，但用 JS `Map<string, string[]>`），内存约 20 万条索引项。
- 对未命中的呼号，取所有相邻字符对的并集作为候选集，再做编辑距离 ≤2 的筛选，按 `annual_rate` 或长度差排序，取 Top-3/5。
- 只在用户点击/告警展开时计算，加 LRU 缓存；**不要**对每条 SPOT 实时做全库编辑距离。
- 自动纠错永远只做“建议”，不自动替换 `spot_call`。

### 7.5 设置开关与 UI / i18n

遵循现有设置体系（唯一 schema：`public/shared/settings/schema.js`）：

建议最小键集（都放在 `data` 域，默认不改变现有行为）：

| key | 类型 | 默认 | 说明 |
|---|---|---|---|
| `scpEnabled` | bool | `false` | 是否启用 SCP 数据（关闭时不下载、不加载、不显示徽标） |
| `scpAlertMode` | enum `off` / `flag` / `drop` | `off` | 告警侧行为：关闭 / 只标记 / 丢弃未命中呼号 |

- 新增键必须同时补 `label` / `zh` / `desc`，并加入 11 种语言的 i18n 词典（`public/js/i18n.js`），保持键集合一致；不要硬编码中英文。
- 设置页会自动按 schema 渲染，不需要写专门的 UI 代码。
- 服务端通过 `lib/settings/service.js` 的 `runtime()` 读取；前端通过现有设置读取路径读取。
- 状态展示建议提供 `GET /api/scp/status`（可用/版本/条数/上次成功时间/stale），由 Node-RED HTTP-in + `dx.scp` 模块实现，风格对齐 `lib/multipliers` 的 `prepare/complete`。

### 7.6 接入点（按改动量从小到大）

1. **只读徽标（最小）**：在 SPOT 记录/告警卡片上显示 `SCP` / `not in SCP`；后端在 spot 序列化时附带 `scpKnown`。
2. **告警标记**：`lib/alerts/service.js` 的 `evaluate()` 里加 `scpKnown` 与 `scp` 元数据；`scpAlertMode=flag` 时只在告警对象上标记，不改变是否通知。
3. **告警过滤**：`scpAlertMode=drop` 时，在规则命中后、`recordHit()` 前丢弃；建议同时要求“呼号结构可疑”（如 `resolveCall()` 失败）才丢弃，降低误杀。
4. **相似呼号**：前端在告警卡片/记录详情里按需调用 `/api/scp/suggest?call=...`，后端用 2-gram 索引返回候选；不要让每条 SPOT 都触发。
5. **倍率矩阵**：不建议改状态计算；最多在单元格呼号列表里加 SCP 标记。

### 7.7 降级与可观测性

- SCP 下载失败、文件损坏、版本回退时：保留上一份可用数据，日志 `warn`，状态接口返回 `stale: true`。
- 启动自检输出：`scp file`、`release`、`count`、`loaded`、`stale`，便于对账（与项目现有 DB 自检风格一致）。
- 不要在 SCP 不可用时改变告警/地图行为；所有 SCP 相关逻辑都必须能“无数据时自动退化为现状”。

### 7.8 分阶段建议

- **P1（推荐先做）**：`MASTER.SCP` 下载 + 内存 `Set` + 状态接口 + 设置开关 + 告警/记录徽标。默认关闭。
- **P2**：`MASTER.LIS` 年出现率 + 相似呼号建议（2-gram + 编辑距离）。
- **P3**：`SCP.DB` 位域元数据（模式/赛事/核验），用于排序或高级筛选；需先解决 Node 18 下的 SQLite 读取方式。

## 附录 B：`.DTA` 解码算法（实测）

```text
charset = "ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789/"   // 37 个字符
offsets = 前 1370 个小端 uint32
  offsets[0] = 5480               // 字符串区起点
  offsets[1369] = 文件长度        // 哨兵
for k in 0..1368:
    start = offsets[k], end = offsets[k+1]
    bucket[k] = 从 start 到 end 的 \0 分隔字符串

bucket 索引 = charset.indexOf(call[i]) * 37 + charset.indexOf(call[i+1])
每个呼号插入其所有不重复的相邻字符对
```

验证：50,020 个正文条目（含 `VER20261106`）产生的索引项总数为 209,089，与文件实际条目数完全一致；随机 300 个呼号预测桶位 300/300 命中。
